# T-004: סקרייפר עמודי משחק

**סטטוס:** שלב ב מומש — בבדיקות ולסקירת QA; ריצה מלאה ממתינה לאישור עמית
**מבצע:** Codex
**תלויות:** T-003 (צריך את רשימת ה-`game_id`)

## מטרה
למשוך את עמוד המשחק לכל משחק ששוחק ולשמור אותו גולמי (4,842 מזהים במחזורים הגולמיים הנוכחיים, כולל משחקים טכניים).

## הסבר כדורגלני
התוצאה הסופית מספרת רק את הסוף. עמוד המשחק מספר את הסיפור: מי הוביל במחצית, מתי נכבשו השערים, האם מישהו הורחק, ומי אימן. מכאן באים פיצ'רים כמו "קבוצה שיודעת לשמור על יתרון" ו"משחק בעשרה".

## שלב א: בדיקת תקינות ראשונית (10 משחקים)
בסקירה של 9.10.2026 אומת שהעמוד הוא HTML סטטי רגיל וקריאת `GET` ישירה מחזירה את כל הנתונים (אין צורך ב-Playwright).
1. לוודא שליפה תקינה של 10 משחקים מדגמיים מעונות שונות (2006/07 עד 2026/27).
2. אימות מבנה ה-HTML והשדות המרכזיים.

## שלב ב: גרידה מלאה
- פלט: `data/raw/ifa/games/{season_id}/{game_id}.html.gz` + `manifest.json`.
- היקף: כ-4,800 עמודים.
- השהיה ≥ 2 שניות (זמן משוער: כ-3.5 שעות).
- המשכיות: ריצה שנקטעה ממשיכה מהמקום שעצרה על בסיס קבצים קיימים.
- מצב `live`: רק משחקים חדשים מאז הריצה הקודמת.

## קריטריוני קבלה

## מימוש שלב ב — 11.10.2026

- מקור יחיד: `data/raw/ifa/rounds`, אימות גודל ו־SHA-256 מול manifest לפני פענוח.
  נבחר snapshot הלייב האחרון שהושלם לפי זמן ההשלמה. אין קריאה מ־data/clean.
- כל game_id מהמחזורים נכלל, גם שמונת משחקי awarded/void; מחזורי מבחן מוחרגים לפי שם הסבב.
  הספירה המקומית: 4,842 (4,802 בהיסטוריה ו־40 בלייב). אין שינוי בדאטה הנקי.
- gzip שומר את בתים המקוריים; manifest מתעד גודל ו־SHA-256 של התוכן וגם של הקובץ הדחוס.
  השמירה עוברת staging, fsync, בדיקת פרטי המשחק/מזהים ופרסום אטומי באמצעות hard link ללא דריסה.
- מחצית, ציר זמן, הרכבים ומאמנים הם מידע אופציונלי: משחק טכני שלא התקיים עשוי להציג 0:0 בלבד.
  התוצאה והתאריך חייבים להיות נוכחים; מזהי קבוצות ועונה חייבים להתאים לשורת המחזור.
- דחויים נשמרים בדחיסה ב־rejected עם סיבה ופרטי הבקשה; לא נוצר עבורם שם סופי.
- קובצי HTML מהמדגם הקודם נשמרים כפי שהם. בריצה מאושרת אפשר לפרסם לצדם gzip לאחר אימות,
  בלי בקשת רשת. זמן/HTTP status קיימים נשמרים; אם מטמון ללא תיעוד, HTTP status הוא null.
- דילוג רק לאחר אימות התוכן, המזהים וה־SHA. מטמון פגום גורם לעצירה בלי שינוי הקובץ הקיים.
- manifest נכתב אחרי כל עמוד; completed רק לאחר אימות כל המזהים שהתבקשו בעונה.
  כשל/KeyboardInterrupt מסומן failed, וריצה חוזרת ממשיכה מהקבצים שפורסמו.
- תעבורה סדרתית: השהיה ≥2 שניות, עד 3 ניסיונות עם backoff לשגיאות requests ו־5xx;
  403/429 עוצרים מיד את כל הריצה ללא retry. ב־CLI מודפסת סיבת העצירה ו־exit code 1.
- `--report` עם --seasons/--live בודק מטמון בלבד, ללא Session או רשת; מציג ספירה לכל עונה,
  קבצים חסרים/פגומים, rejected וסטטוס manifest. חריגה מחזירה exit code 1.
- fixtures: עמודים אמיתיים מהמדגם של 2006/07, 2010/11, 2011/12 ו־2014/15; עבור 732312 יש כרגע
  fixture סינתטי מסומן למקרה ללא אירועים. נדרש עותק HTML אמיתי מקלוד להשלמת הכיסוי מול המקור.

## שער הריצה המלאה

קוד → PR → QA קלוד → אישור עמית → ריצה. לפני הריצה יש להשבית מצב שינה זמנית ב־Windows,
ולשחזר את ההגדרה המקורית בסיום. כעת לא שונו הגדרות החשמל ולא בוצעו בקשות רשת.
אחרי שתי הפקודות יש להריץ דוח היסטוריה ודוח live: ספירה תואמת למחזורי raw, אין missing/invalid,
rejected ריק ו־manifest completed בכל העונות. דחויים קודמים נשמרים לתיעוד ואינם נמחקים כדי לעבור בדיקה;
אם קיימים, יש לדווח לעמית גם כאשר ניסיון מאוחר יותר הצליח.
