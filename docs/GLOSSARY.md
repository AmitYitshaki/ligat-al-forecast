# מילון מושגים

> כל מושג שמופיע בפרויקט, מוסבר בקצרה. כל סוכן שמציג מושג חדש מוסיף אותו לכאן.

---

## כדורגל ומבנה הליגה

| מושג | הסבר |
| --- | --- |
| **עונה סדירה** | השלב שבו כל קבוצה פוגשת כל קבוצה (כיום 26 מחזורים) |
| **פלייאוף עליון / תחתון** | אחרי העונה הסדירה: 6 הראשונות נלחמות על האליפות, 8 האחרונות על ההישרדות. הנקודות נגררות |
| **חלוקת נקודות** | שיטה שהייתה נהוגה בעבר: לפני הפלייאוף הנקודות חולקו לשניים, כדי לצמצם פערים |
| **הורדת נקודות** | עונש משמעתי או כלכלי שמוריד נקודות לקבוצה. בפרויקט מתעלמים מהן |
| **מצב מחצית** | התוצאה בהפסקה. ממנה מודדים "ניהול משחק": האם קבוצה שמובילה יודעת לסגור |
| **שובר שוויון** | הכלל שקובע מי מעל מי כשיש שוויון בנקודות (הפרש שערים, מפגשים ישירים וכו') |
| **יתרון ביתיות** | הנטייה של קבוצות להצליח יותר בבית: קהל, היכרות עם המגרש, בלי נסיעה |
| **אפקט התאמה** | קבוצה שמצליחה (או נכשלת) מול יריבה מסוימת יותר ממה שהחוזק הכללי שלהן צופה |

## סטטיסטיקה ומודלים

| מושג | הסבר |
| --- | --- |
| **התפלגות פואסון** | התפלגות שמתארת "כמה פעמים אירוע נדיר קורה בפרק זמן". מתאימה למספר שערים במשחק. פרמטר אחד, λ, שהוא הממוצע הצפוי |
| **λ (למדא)** | מספר השערים הצפוי של קבוצה במשחק. מודל 1 חוזה λ לכל קבוצה |
| **Dixon-Coles** | מודל קלאסי לכדורגל: לכל קבוצה כוח התקפה וכוח הגנה, ותיקון לתוצאות נמוכות (0:0, 1:1) שפואסון רגיל מזלזל בהן |
| **Elo** | דירוג שמתעדכן אחרי כל משחק: ניצחון מפתיע מעלה הרבה, ניצחון צפוי מעלה מעט. במקור משחמט |
| **XGBoost** | אלגוריתם שבונה הרבה עצי החלטה קטנים, כל אחד מתקן את הטעויות של הקודמים (gradient boosting) |
| **Ridge** | רגרסיה ליניארית עם "קנס" על מקדמים גדולים. מונעת מהמודל להיצמד לרעש כשיש מעט דאטה |
| **סימולציית מונטה קרלו** | להריץ את העונה אלפי פעמים עם תוצאות אקראיות לפי ההסתברויות, ולספור באיזה אחוז מהפעמים כל דבר קרה |
| **שארית (residual)** | ההפרש בין המציאות לחיזוי. מודל 2 לומד לחזות את השארית של הסימולציה |

## אימון והערכה

| מושג | הסבר |
| --- | --- |
| **התאמת יתר (overfitting)** | מודל ש"שינן" את הדאטה, כולל הרעש, ולכן נכשל על דאטה חדש |
| **דליפת מידע (leakage)** | שימוש, בטעות, במידע שלא היה ידוע בזמן החיזוי. מייצר תוצאות טובות מדי בבדיקה וכישלון במציאות |
| **walk-forward** | הערכה כרונולוגית: מאמנים על העבר, חוזים את העונה הבאה, מתקדמים עונה. כמו בשימוש אמיתי |
| **עונות החזקה (holdout)** | עונות שלא נוגעים בהן עד הבדיקה הסופית, כדי לקבל הערכה אמינה |
| **דעיכה בזמן / זמן מחצית** | משחקים ישנים מקבלים משקל קטן יותר. זמן מחצית = אחרי כמה עונות משקל המשחק יורד לחצי |
| **כיווץ (shrinkage)** | משיכת אומדן שמבוסס על מעט דאטה לכיוון ערך ניטרלי. 3 מפגשים → כמעט אפס; 30 מפגשים → כמעט האומדן המלא |
| **RPS** | Ranked Probability Score. מדד לאיכות הסתברויות לבית/תיקו/חוץ, שמתחשב בכך שתיקו "קרוב" יותר לניצחון מאשר הפסד. נמוך = טוב |
| **log loss** | מדד שמעניש בחומרה חיזוי בטוח שהתברר כשגוי |
| **כיול (calibration)** | האם אירועים שקיבלו 60% באמת קורים ב-60% מהמקרים |
| **ablation** | הסרת קבוצת פיצ'רים אחת ובדיקה כמה המודל נפגע. אם לא נפגע, הפיצ'ר מיותר |
| **bootstrap** | דגימה חוזרת של הדאטה כדי לאמוד אי-ודאות, למשל האם הפרש בין שני מודלים מובהק |
| **SHAP** | שיטה שמראה, לכל חיזוי, כמה כל פיצ'ר דחף אותו למעלה או למטה |
| **בנצ'מרק** | מודל פשוט שכל מודל מורכב חייב לנצח כדי להצדיק את עצמו |

## הנדסת תוכנה

| מושג | הסבר |
| --- | --- |
| **ממשק (ABC / Protocol)** | הגדרה של "מה מחלקה חייבת לדעת לעשות" בלי לקבוע איך. מאפשר להחליף מימוש אחד באחר |
| **Strategy pattern** | כמה מימושים לאותו ממשק, ובוחרים ביניהם בזמן ריצה (אצלנו: מודלים) |
| **Repository pattern** | שכבה אחת שאחראית על קריאה וכתיבה של דאטה, כך ששאר הקוד לא יודע איפה הקבצים |
| **pandera** | ספרייה שבודקת שטבלת pandas עומדת בסכמה: טיפוסים, טווחים, ערכים חסרים |
| **Golden file** | קובץ קלט שמור עם פלט צפוי קבוע, לבדיקה שהפענוח לא נשבר |
| **Bump chart** | גרף שמראה את המיקום בטבלה לאורך זמן: כל קבוצה קו, ציר y הפוך (מקום 1 למעלה) |
| **מטמון לפי hash** | שמירת "טביעת אצבע" של הקלט; אם לא השתנתה, לא בונים מחדש |
| **CI** | הרצה אוטומטית של בדיקות על כל שינוי (אצלנו GitHub Actions) |
