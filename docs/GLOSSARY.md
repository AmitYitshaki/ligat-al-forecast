# מילון מושגים

> כל מושג שמופיע בפרויקט, מוסבר בקצרה. כל סוכן שמציג מושג חדש מוסיף אותו לכאן.

---

## כדורגל ומבנה הליגה

| מושג | הסבר |
| --- | --- |
| **עונה סדירה** | השלב שבו כל קבוצה פוגשת כל קבוצה (כיום 26 מחזורים) |
| **פלייאוף עליון / תחתון** | אחרי העונה הסדירה: 6 הראשונות נלחמות על האליפות, 8 האחרונות על ההישרדות. הנקודות נגררות |
| **חלוקת נקודות** | שיטה שהייתה נהוגה בעבר: לפני הפלייאוף הנקודות חולקו לשניים, כדי לצמצם פערים |
| **הורדת נקודות** | עונש משמעתי או כלכלי שמוריד נקודות לקבוצה. בפרויקט מתעלמים מהן |
| **מצב מחצית** | התוצאה בהפסקה. ממנה מודדים "ניהול משחק": האם קבוצה שמובילה יודעת לסגור |
| **שובר שוויון** | הכלל שקובע מי מעל מי כשיש שוויון בנקודות (הפרש שערים, מפגשים ישירים וכו') |
| **יתרון ביתיות** | הנטייה של קבוצות להצליח יותר בבית: קהל, היכרות עם המגרש, בלי נסיעה |
| **אפקט התאמה** | קבוצה שמצליחה (או נכשלת) מול יריבה מסוימת יותר ממה שהחוזק הכללי שלהן צופה |

## סטטיסטיקה ומודלים

| מושג | הסבר |
| --- | --- |
| **התפלגות פואסון** | התפלגות שמתארת "כמה פעמים אירוע נדיר קורה בפרק זמן". מתאימה למספר שערים במשחק. פרמטר אחד, λ, שהוא הממוצע הצפוי |
| **λ (למדא)** | מספר השערים הצפוי של קבוצה במשחק. רכיב M2 חוזה λ לכל קבוצה |
| **Dixon-Coles** | מודל קלאסי לכדורגל: לכל קבוצה כוח התקפה וכוח הגנה, ותיקון לתוצאות נמוכות (0:0, 1:1) שפואסון רגיל מזלזל בהן |
| **Elo** | דירוג שמתעדכן אחרי כל משחק: ניצחון מפתיע מעלה הרבה, ניצחון צפוי מעלה מעט. במקור משחמט |
| **XGBoost** | אלגוריתם שבונה הרבה עצי החלטה קטנים, כל אחד מתקן את הטעויות של הקודמים (gradient boosting) |
| **Ridge** | רגרסיה ליניארית עם "קנס" על מקדמים גדולים. מונעת מהמודל להיצמד לרעש כשיש מעט דאטה |
| **סימולציית מונטה קרלו** | להריץ את העונה אלפי פעמים עם תוצאות אקראיות לפי ההסתברויות, ולספור באיזה אחוז מהפעמים כל דבר קרה |
| **שארית (residual)** | ההפרש בין המציאות לחיזוי; אחת החלופות למחקר השילוב ב-M6 היא ללמוד תיקון לשארית הסימולציה |
| **מטריצת תוצאות (Score Matrix)** | מטריצה 9×9 (81 תאים, 0:0 עד 8:8) המייצגת את ההסתברות המשותפת לכל תוצאה אפשרית במשחק, מנורמלת לסכום 1 |
| **מטריצת 14×14** | מטריצת הפלט הסופי של הפרויקט: לכל אחת מ-14 הקבוצות בליגה, ההסתברות לסיים בכל אחד מ-14 המיקומים (1 עד 14). כל שורה מסתכמת ל-1 |
| **חשיבות משחק (Match Importance / Leverage)** | חלופה למדד חשיבות תחרותית: P(יעד \| ניצחון) − P(יעד \| הפסד). ההפרש בטווח ‎−1 עד 1; הגדרת הציון 0–1 וכלל הטיפול בערכים שליליים ייקבעו במחקר לפי VISION §7. זה אינו מדד למצב פסיכולוגי |
| **ממוצע נע (rolling)** | ממוצע של מדד על פני חלון N המשחקים האחרונים של קבוצה, מחושב בקפדנות רק ממשחקים שקדמו למשחק הנחזה (ללא דליפה) |
| **EWMA** | ממוצע נע משוקלל מעריכית (Exponentially Weighted Moving Average), שבו משחקים קרובים בזמן מקבלים משקל גבוה יותר ממשחקים רחוקים |

## רכיבי השרשרת (VISION §3–§5)

| רכיב | שם בארכיטקטורה | מחברת | תיאור ותפקיד |
| --- | --- | --- | --- |
| **`prematch`** | M0 | 03 | **מצב לפני שריקה (`as_of`):** הפקת מצב טבלה מחושב לפי תאריך (A), כושר נע (5/10/20/EWMA) ו-Elo (B), והקשר עונתי ($t-1$) ושווי סגל (C). קלט בסיסי נקי מדליפה לכל המשך השרשרת |
| **`motivation`** | M1 | 04 | **פענוח מוטיבציה / חשיבות תחרותית:** הפקת ציון 0–1 לכל קבוצה (`home_motivation`, `away_motivation`) בקנה מידה של ציפיית Elo ומול סימולטור Elo פשוט לחשיבות משחק (Leverage). הגדרת הציון מוכרעת במחקר לפי החלטה ה-2 |
| **`goals`** | M2 | 05 | **שערים צפויים:** מודל XGBoost עם objective של פואסון החוזה $\lambda_{\text{home}}, \lambda_{\text{away}}$ לכל משחק, לצד כוח הבקעה/ספיגה כללי מול יריב ניטרלי. עמידות המוטיבציה נבחנת ב-ablation משולש |
| **`scores`** | M3 | 06 | **התפלגות תוצאה מדויקת:** גזירת מטריצה 9×9 (0:0 עד 8:8) באמצעות פואסון + תיקון Dixon-Coles או פואסון דו-משתני, והפקת הסתברויות עקביות לתוצאת המשחק $P(\text{Home Win}), P(\text{Draw}), P(\text{Away Win})$ מאותה מטריצה |
| **`season_sim`** | M4 | 07 | **סימולציית עונה (Monte Carlo):** הרצת עשרות אלפי מסלולי עונה ממשחקים שנותרו ועד סוף הפלייאוף. מעדכנת בתוך כל מסלול טבלה, כושר, Elo ומוטיבציה, ומספקת תחזית טבלה מלאה ראשונה |
| **`table_model`** | M5 | 08 | **מודל "טבלה בלבד":** מודל מקרו שלומד מטבלאות מחושבות בעבר (נקודות + הפרש שערים + מחזור ושלב בלבד, ללא משחקים בודדים) ומפיק התפלגות נקודות ומיקום להמשך העונה |
| **`blend`** | M6 | 09 | **השוואה ושילוב נלמד:** שילוב מכויל של תוצרי הסימולציה (`season_sim`, M4) ותוצרי מודל הטבלה (`table_model`, M5) בנקודת הפיצול ובסוף העונה, המפיק את התחזית הסופית (מטריצה 14×14) |

## אימון והערכה

| מושג | הסבר |
| --- | --- |
| **שלד מהלך (Walking Skeleton)** | חלופת פיתוח שנשקלה בגרסה 3 (בניית שרשרת פשוטה מקצה לקצה ללא מוטיבציה), והוחלפה בגרסה 4 בסדר העבודה של 9 מחברות סדרתיות לפי עמית (החלטה ה-1), שבו המוטיבציה מפוענחת לפני מודל השערים ומחברת 02 מוקדשת לסטטיסטיקות ליגה תיאוריות |
| **out-of-fold (OOF)** | תחזיות לשורות שלא נכללו באימון המודל שהפיק אותן. בפרויקט נדרש OOF כרונולוגי מקונן: גם קלטי האימון של רכיב ההמשך נוצרו מחלונות מוקדמים יותר בלבד, לפני הזנתם לשרשרת |
| **Residual Fallback** | מודל ההמשך מקבל גם פיצ'רי עבר רלוונטיים לצד פלט רכיב הביניים. הדבר אינו מבטיח הגנה משגיאה; בודקים את העמידות בניסויי רגישות לפלט שגוי או חסר |
| **Common Random Numbers (CRN)** | טכניקה בסימולציות מונטה קרלו שבה משתמשים באותו זרע ומספרים אקראיים לשני תרחישים מושווים (למשל ניצחון מול הפסד בחישוב חשיבות משחק), כדי לבודד את ההשפעה ולהקטין רעש דגימה |
| **התאמת יתר (overfitting)** | מודל ש"שינן" את הדאטה, כולל הרעש, ולכן נכשל על דאטה חדש |
| **דליפת מידע (leakage)** | שימוש, בטעות, במידע שלא היה ידוע בזמן החיזוי. מייצר תוצאות טובות מדי בבדיקה וכישלון במציאות |
| **walk-forward** | הערכה כרונולוגית: מאמנים על העבר, חוזים את העונה הבאה, מתקדמים עונה. כמו בשימוש אמיתי |
| **expanding window** | חלון אימון שמתחיל משלוש עונות ומתרחב בעונה בכל fold; עונת הוולידציה תמיד אחריו |
| **עונות החזקה (holdout)** | עונות שלא נוגעים בהן עד הבדיקה הסופית, כדי לקבל הערכה אמינה (בפרויקט: 2024/25 ו-2025/26) |
| **דעיכה בזמן / זמן מחצית** | משחקים ישנים מקבלים משקל קטן יותר. זמן מחצית = אחרי כמה עונות משקל המשחק יורד לחצי |
| **כיווץ (shrinkage)** | משיכת אומדן שמבוסס על מעט דאטה לכיוון ערך ניטרלי. 3 מפגשים → כמעט אפס; 30 מפגשים → כמעט האומדן המלא |
| **RPS** | Ranked Probability Score. מדד לאיכות הסתברויות לבית/תיקו/חוץ, שמתחשב בכך שתיקו "קרוב" יותר לניצחון מאשר הפסד. נמוך = טוב |
| **log loss** | מדד שמעניש בחומרה חיזוי בטוח שהתברר כשגוי (בפרויקט: מחושב גם על התוצאה המדויקת מתוך מטריצת ה-9×9) |
| **כיול (calibration)** | האם אירועים שקיבלו 60% באמת קורים ב-60% מהמקרים |
| **ablation** | הסרת קבוצת פיצ'רים אחת ובדיקה כמה המודל נפגע. אם לא נפגע, הפיצ'ר מיותר |
| **השלמת ערכים (imputation)** | מילוי ערכים חסרים בדאטה לפי כלל סטטיסטי (כמו חציון או ממוצע). מתבצע רק בשלב הפיצ'רים, לעולם לא בדאטה הנקי |
| **bootstrap** | דגימה חוזרת של הדאטה כדי לאמוד אי-ודאות, למשל האם הפרש בין שני מודלים מובהק |
| **SHAP** | שיטה שמראה, לכל חיזוי, כמה כל פיצ'ר דחף אותו למעלה או למטה |
| **בנצ'מרק** | מודל פשוט שכל מודל מורכב חייב לנצח כדי להצדיק את עצמו |
| **בנצ'מרק B0** | בנצ'מרק הבסיס הנאיבי ביותר: חיזוי הסתברויות קבועות לבית/תיקו/חוץ לפי שיעורי הניצחון ההיסטוריים בליגה |

## הנדסת תוכנה

| מושג | הסבר |
| --- | --- |
| **ממשק (ABC / Protocol)** | הגדרה של "מה מחלקה חייבת לדעת לעשות" בלי לקבוע איך. מאפשר להחליף מימוש אחד באחר |
| **Strategy pattern** | כמה מימושים לאותו ממשק, ובוחרים ביניהם בזמן ריצה (אצלנו: מודלים) |
| **Repository pattern** | שכבה אחת שאחראית על קריאה וכתיבה של דאטה, כך ששאר הקוד לא יודע איפה הקבצים |
| **pandera** | ספרייה שבודקת שטבלת pandas עומדת בסכמה: טיפוסים, טווחים, ערכים חסרים |
| **Golden file** | קובץ קלט שמור עם פלט צפוי קבוע, לבדיקה שהפענוח לא נשבר |
| **Bump chart** | גרף שמראה את המיקום בטבלה לאורך זמן: כל קבוצה קו, ציר y הפוך (מקום 1 למעלה) |
| **מטמון לפי hash** | שמירת "טביעת אצבע" של הקלט; אם לא השתנתה, לא בונים מחדש |
| **CI** | הרצה אוטומטית של בדיקות על כל שינוי (אצלנו GitHub Actions) |
