# ויזואליזציה

> כל גרף בפרויקט מוגדר פעם אחת כפונקציה, נבנה מחדש מהדאטה הנוכחי בפקודה אחת, ומופיע בגלריה אחת.
> עודכן לאחרונה: 8.10.2026

---

## 1. עקרונות

1. **גרף הוא קוד, לא קובץ.** אף גרף לא נערך ידנית. כל גרף הוא פונקציה שמקבלת את הדאטה ומחזירה figure. שינוי בדאטה → `ligat viz build` → כל הגרפים מעודכנים.
2. **כל גרף עונה על שאלה כדורגלנית אחת.** השאלה כתובה בהגדרת הגרף ומוצגת בגלריה. גרף בלי שאלה לא נכנס.
3. **הכותרת היא התשובה.** "יתרון הביתיות נחלש מאז 2015", לא "יתרון ביתיות לפי עונה". כשהכותרת תלויה בדאטה, היא מחושבת מהדאטה.
4. **אותם גרפים בכל מקום.** הגלריה, המחברות, הדוחות והדשבורד העתידי משתמשים באותן פונקציות. אין גרף שקיים רק במחברת.
5. **אינטראקטיבי לחקירה, סטטי להצגה.** כל גרף נשמר גם כ-HTML (ריחוף, זום, סינון) וגם כ-PNG (למצגות ול-README).

## 2. ארכיטקטורה

```
ligat/viz/
├── spec.py        # ChartSpec: ההגדרה של גרף
├── registry.py    # @chart(...) רושם גרף; list / get / by_stage
├── theme.py       # צבעים, פונטים, גדלים, תבנית Plotly אחידה
├── build.py       # בונה גרפים, שומר HTML + PNG, מנהל מטמון לפי hash
├── gallery.py     # מייצר reports/gallery/index.html
└── charts/
    ├── data_quality.py
    ├── overview.py
    ├── game_flow.py
    ├── eda.py
    ├── model.py
    └── forecast.py
```

### ChartSpec

| שדה | משמעות |
| --- | --- |
| `name` | מזהה ייחודי, `snake_case` |
| `stage` | `data_quality` / `overview` / `game_flow` / `eda` / `model` / `forecast` |
| `football_question` | השאלה שהגרף עונה עליה, בעברית |
| `inputs` | אילו דאטה סטים הוא קורא (`matches`, `round_tables`...). קובע מתי צריך לבנות מחדש |
| `params` | פרמטרים אופציונליים, למשל עונה או קבוצה. ברירת מחדל = העונה האחרונה |
| `func` | הפונקציה: מקבלת `Repository` + params, מחזירה `plotly.graph_objects.Figure` |

### דוגמה

```python
@chart(
    name="home_advantage_by_season",
    stage="overview",
    football_question="האם יתרון הביתיות בליגה משתנה לאורך השנים?",
    inputs=["matches"],
)
def home_advantage_by_season(repo: Repository) -> go.Figure:
    m = repo.matches()
    shares = outcome_shares_by_season(m)          # פונקציה מ-ligat/analysis, לא כאן
    fig = stacked_share_bars(shares, order=["home", "draw", "away"])
    fig.update_layout(title=headline_home_advantage(shares))  # כותרת = תשובה, מחושבת
    return fig
```

החישוב (`outcome_shares_by_season`) יושב ב-`ligat/analysis/`, לא בתוך הגרף. כך אותו חישוב משמש גם בטסטים ובדוחות.

### הבנייה והעדכון

| פקודה | מה עושה |
| --- | --- |
| `ligat viz list` | כל הגרפים הרשומים, לפי שלב |
| `ligat viz build` | בונה את כל מה שהדאטה שלו השתנה מאז הבנייה האחרונה |
| `ligat viz build --stage overview` | שלב אחד |
| `ligat viz build --chart season_race --param season=2025/26` | גרף אחד עם פרמטר |
| `ligat viz build --force` | בונה הכול מחדש |
| `ligat viz gallery` | מייצר את הגלריה ופותח אותה |

**מטמון:** לכל גרף נשמר hash של קבצי הקלט שלו (`inputs`) ושל הקוד שלו. אם אף אחד מהם לא השתנה, הגרף לא נבנה מחדש. שינוי בדאטה סט אחד בונה מחדש רק את הגרפים שתלויים בו.

**פלט:**
```
reports/
├── figures/{stage}/{name}.html
├── figures/{stage}/{name}.png
└── gallery/index.html     # כל הגרפים לפי שלב: שאלה, גרף, תאריך בנייה, גרסת דאטה
```

`reports/figures/` לא נשמר ב-Git (נבנה מחדש). PNG נבחרים ל-README נשמרים ב-`docs/img/`.

## 3. סגנון

- **ספרייה:** Plotly (אינטראקטיבי), עם `kaleido` לייצוא PNG.
- **עברית:** כותרות ותוויות בעברית. Plotly מציג עברית תקין; לבדוק כל גרף חדש בגלריה.
- **צבע:** אפור ניטרלי לכל הקבוצות, וצבע הדגשה אחד לקבוצה או לנקודה שהגרף מדבר עליה. צבעים קבועים למשמעויות: בית / תיקו / חוץ תמיד באותם שלושה צבעים בכל הפרויקט.
- **פחות זה יותר:** בלי רשתות כבדות, בלי צללים, בלי תלת-ממד. ציר y מתחיל מאפס בגרפי עמודות.
- **כל ציר עם יחידות:** "נקודות", "שערים למשחק", "% מהמשחקים".
- **ערכת העיצוב** מוגדרת פעם אחת ב-`theme.py` ומוחלת על כל גרף אוטומטית.

## 4. קטלוג הגרפים

### שלב `data_quality`: האם הדאטה שלם ונכון?

| גרף | שאלה כדורגלנית | סוג |
| --- | --- | --- |
| `coverage_heatmap` | האם יש לנו כל משחק בכל מחזור בכל עונה? | מפת חום: עונה × מחזור, צבע = משחקים שנמצאו / צפויים |
| `points_reconciliation` | איפה הנקודות הרשמיות שונות מהחישוב, ולמה (חלוקה / הורדה)? | עמודות לפי עונה וקבוצה |
| `details_availability` | אילו פרטים מעמוד המשחק קיימים בכל עונה? | מפת חום: עונה × שדה |
| `venue_usage` | אילו קבוצות שיחקו משחקי בית מחוץ לאצטדיון הקבוע? | עמודות |

### שלב `overview`: איך נראית ליגת העל?

| גרף | שאלה כדורגלנית | סוג |
| --- | --- | --- |
| `goals_per_match_distribution` | כמה שערים יש במשחק טיפוסי, והאם זה מתנהג כמו פואסון? | היסטוגרמה + עקומת פואסון |
| `home_advantage_by_season` | האם יתרון הביתיות משתנה לאורך השנים? | עמודות 100% מוערמות: בית / תיקו / חוץ |
| `goals_trend` | האם הליגה נהייתה התקפית או הגנתית יותר? | קו: שערים למשחק לפי עונה |

| `competitiveness_by_season` | באילו עונות הליגה הייתה צמודה ובאילו הייתה הכרעה מוקדמת? | Box plot של נקודות למשחק לפי עונה |
| `team_strength_heatmap` | אילו קבוצות שלטו ומתי? שושלות, עליות וירידות | מפת חום: קבוצה × עונה, צבע = נקודות למשחק |
| `season_race` | איך התפתח המאבק על האליפות וההישרדות בעונה נתונה? | Bump chart: מיקום לפי מחזור (פרמטר: עונה) |
| `points_trajectories` | מתי האלופה ברחה, ומתי היורדות נפלו? | קווי נקודות מצטברות לפי מחזור (פרמטר: עונה) |
| `promoted_teams_fate` | איך מסתדרות קבוצות עולות בעונה הראשונה? | התפלגות מיקום סופי של עולות |

## 5. איך מוסיפים גרף

1. מגדירים שאלה כדורגלנית אחת.
2. מוסיפים שורה לקטלוג בסעיף 4.
3. כותבים פונקציה עם `@chart(...)` בקובץ השלב.
4. מוסיפים אותה לטסט "כל גרף נבנה על דאטה דמה".
5. `ligat viz build --chart NAME` ובודקים בגלריה.
6. **⏸ מציגים לעמית** את הגרף ואת הכותרת-תשובה לפני מיזוג.
